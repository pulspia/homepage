# 관리자 페이지 종합 테스트 계획

## 📋 테스트 개요

이 문서는 Pulspia 관리자 페이지 (Phase 1-6)의 종합 테스트 계획을 설명합니다.

**테스트 목표**: 모든 관리자 페이지 기능이 정상적으로 동작하며, 성능 및 보안 요구사항을 충족하는지 검증

**테스트 환경**:
- 로컬 개발 환경: http://localhost:3000
- 모니터링 서버: http://localhost:8002
- 데이터베이스: Supabase

## 🧪 Phase별 테스트 시나리오

### Phase 1: 기본 인프라 구축

#### 1.1 Supabase 데이터베이스 테스트

**테스트 항목**:
- [ ] 8개 테이블이 모두 생성되었는지 확인
  ```sql
  SELECT table_name FROM information_schema.tables
  WHERE table_schema = 'public'
  AND table_name IN (
    'admin_settings', 'visitor_analytics', 'page_views',
    'system_logs', 'server_metrics', 'ip_blacklist',
    'admin_activity_logs', 'alert_history'
  );
  ```

- [ ] RLS 정책이 활성화되었는지 확인
  ```sql
  SELECT tablename, rowsecurity FROM pg_tables
  WHERE schemaname = 'public';
  ```

- [ ] Realtime이 4개 테이블에 활성화되었는지 확인
  - Supabase Dashboard → Database → Replication
  - `visitor_analytics`, `server_metrics`, `system_logs`, `alert_history` 확인

#### 1.2 관리자 인증 테스트

**테스트 케이스**:

**TC-1.2.1: 로그인 성공**
- **단계**:
  1. http://localhost:3000/admin 접속
  2. 유효한 이메일/비밀번호 입력
  3. "로그인" 버튼 클릭
- **예상 결과**: 관리자 대시보드 화면 표시

**TC-1.2.2: 잘못된 인증 정보로 로그인 시도**
- **단계**:
  1. http://localhost:3000/admin 접속
  2. 잘못된 이메일/비밀번호 입력
  3. "로그인" 버튼 클릭
- **예상 결과**: "이메일 또는 비밀번호가 올바르지 않습니다." 에러 메시지 표시

**TC-1.2.3: 로그아웃**
- **단계**:
  1. 로그인 상태에서 "로그아웃" 버튼 클릭
- **예상 결과**: 로그인 페이지로 리다이렉트

#### 1.3 AdminLogin 단위 테스트

**테스트 명령어**:
```bash
npm test -- AdminLogin.test.js --watchAll=false
```

**예상 결과**: 9/9 테스트 통과

### Phase 2: 실시간 접속자 추적 및 통계

#### 2.1 방문자 추적 테스트

**TC-2.1.1: 방문자 세션 생성**
- **단계**:
  1. 새 브라우저 시크릿 모드로 http://localhost:3000 접속
  2. Supabase → Table Editor → `visitor_analytics` 확인
- **예상 결과**: 새로운 방문자 레코드 생성

**TC-2.1.2: 페이지 조회 추적**
- **단계**:
  1. Home, News, Contact 페이지를 차례로 방문
  2. Supabase → `page_views` 테이블 확인
- **예상 결과**: 각 페이지별 조회 기록 생성

**TC-2.1.3: Heartbeat 기능**
- **단계**:
  1. 페이지를 2분 이상 열어둠
  2. `visitor_analytics` 테이블의 `last_activity` 확인
- **예상 결과**: 2분마다 `last_activity` 업데이트

#### 2.2 실시간 접속자 컴포넌트 테스트

**TC-2.2.1: 실시간 접속자 목록 표시**
- **단계**:
  1. 관리자 페이지 → 대시보드 탭
  2. "실시간 접속자" 섹션 확인
- **예상 결과**: 현재 활성 방문자 목록과 정보 (디바이스, 브라우저, OS) 표시

**TC-2.2.2: Realtime 업데이트**
- **단계**:
  1. 관리자 페이지를 열어둠
  2. 다른 브라우저에서 사이트 접속
  3. 관리자 페이지의 실시간 접속자 목록 확인
- **예상 결과**: 새로운 방문자가 자동으로 목록에 추가

#### 2.3 방문자 통계 대시보드 테스트

**TC-2.3.1: 통계 카드 표시**
- **단계**:
  1. 관리자 페이지 → 대시보드 탭
  2. "전체 방문자", "오늘 방문자" 카드 확인
- **예상 결과**: 정확한 방문자 수 표시

**TC-2.3.2: 차트 시각화**
- **단계**:
  1. 유입 경로 차트, 디바이스 유형 차트, 브라우저 분포 차트 확인
- **예상 결과**: Recharts로 데이터가 올바르게 시각화됨

### Phase 3: 시스템 모니터링

#### 3.1 모니터링 서버 테스트

**TC-3.1.1: 모니터링 서버 시작**
- **명령어**:
  ```bash
  cd server && node monitor.js
  ```
- **예상 결과**: "Monitoring server running on http://localhost:8002" 메시지 표시

**TC-3.1.2: Health Check API**
- **명령어**:
  ```bash
  curl http://localhost:8002/health
  ```
- **예상 결과**: `{"status":"OK","timestamp":"..."}`

**TC-3.1.3: Metrics API**
- **명령어**:
  ```bash
  curl http://localhost:8002/api/metrics
  ```
- **예상 결과**: CPU, Memory, Disk 사용량 JSON 응답

#### 3.2 SystemMonitoring 컴포넌트 테스트

**TC-3.2.1: 서버 상태 표시**
- **단계**:
  1. 모니터링 서버가 실행 중인지 확인
  2. 관리자 페이지 → 시스템 모니터링 탭
- **예상 결과**: "모니터링 서버 온라인" 메시지와 실시간 메트릭 표시

**TC-3.2.2: 서버 오프라인 상태 처리**
- **단계**:
  1. 모니터링 서버 종료
  2. 관리자 페이지 → 시스템 모니터링 탭
- **예상 결과**: "모니터링 서버 오프라인" 메시지와 서버 시작 명령어 표시

**TC-3.2.3: 메트릭 임계치 색상**
- **단계**:
  1. 시스템 모니터링 탭에서 CPU/RAM/Disk 카드 확인
- **예상 결과**:
  - 80% 이상: 빨간색
  - 60-80%: 노란색
  - 60% 미만: 초록색

**TC-3.2.4: 데이터베이스 헬스 체크**
- **단계**:
  1. 시스템 모니터링 탭에서 "데이터베이스 정상" 카드 확인
- **예상 결과**: "✅ 데이터베이스 정상" 메시지와 응답 시간 표시

#### 3.3 ErrorLogs 컴포넌트 테스트

**TC-3.3.1: 로그 필터링**
- **단계**:
  1. 관리자 페이지 → 에러 로그 탭
  2. "전체", "오류", "경고", "정보" 버튼 클릭
- **예상 결과**: 선택한 레벨의 로그만 표시

**TC-3.3.2: 로그 검색**
- **단계**:
  1. 에러 로그 탭에서 검색창에 키워드 입력
- **예상 결과**: 키워드가 포함된 로그만 필터링되어 표시

**TC-3.3.3: Realtime 로그 업데이트**
- **단계**:
  1. 에러 로그 탭을 열어둠
  2. 모니터링 서버 또는 앱에서 에러 발생
- **예상 결과**: 새 로그가 자동으로 목록 상단에 추가

### Phase 4: 알람 시스템

#### 4.1 AlertSystem 컴포넌트 테스트

**TC-4.1.1: 알람 설정 저장**
- **단계**:
  1. 관리자 페이지 → 알람 시스템 탭
  2. CPU/RAM/Disk 임계치 값 변경
  3. 수신 이메일 주소 입력
  4. "설정 저장" 버튼 클릭
- **예상 결과**: "설정이 저장되었습니다." 알림 표시

**TC-4.1.2: 테스트 알람 발송**
- **단계**:
  1. 알람 시스템 탭에서 "테스트 알람 발송" 버튼 클릭
  2. 설정한 이메일 주소 확인
- **예상 결과**: 테스트 알람 이메일 수신

**TC-4.1.3: 임계치 초과 시 자동 알람**
- **단계**:
  1. CPU 임계치를 낮게 설정 (예: 10%)
  2. 5분 대기 (자동 체크 주기)
  3. 이메일 확인
- **예상 결과**: CPU 사용량 초과 알람 이메일 수신

**TC-4.1.4: 중복 알람 방지**
- **단계**:
  1. 임계치 초과 상태 유지
  2. 1시간 내에 추가 알람이 발송되지 않는지 확인
- **예상 결과**: 동일한 알람이 1시간 내에 중복 발송되지 않음

**TC-4.1.5: 알람 이력 표시**
- **단계**:
  1. 알람 시스템 탭 → "알람 이력" 섹션 확인
- **예상 결과**: 발송된 알람 목록 표시 (시간, 유형, 심각도)

#### 4.2 EmailJS 통합 테스트

**전제 조건**: EmailJS에 `template_alert` 템플릿 생성 필요

**템플릿 변수**:
- `{{to_email}}`: 수신자 이메일
- `{{resource_type}}`: CPU/RAM/Disk/TEST
- `{{current_value}}`: 현재 사용량
- `{{threshold}}`: 임계치
- `{{timestamp}}`: 발송 시각
- `{{site_name}}`: Pulspia

### Phase 5: 보안 기능

#### 5.1 IPBlacklist 컴포넌트 테스트

**TC-5.1.1: IP 차단 추가**
- **단계**:
  1. 관리자 페이지 → 보안 설정 탭
  2. IP 주소 입력 (예: 192.168.1.100)
  3. 차단 사유 입력 (예: "테스트 차단")
  4. "차단 추가" 버튼 클릭
- **예상 결과**: 차단 목록에 IP 추가되고 `admin_activity_logs`에 기록

**TC-5.1.2: 잘못된 IP 형식 검증**
- **단계**:
  1. 잘못된 IP 형식 입력 (예: "abc.def.ghi.jkl")
  2. "차단 추가" 버튼 클릭
- **예상 결과**: "올바른 IP 주소 형식이 아닙니다." 에러 메시지

**TC-5.1.3: IP 차단 해제 (활성화/비활성화)**
- **단계**:
  1. 차단된 IP의 "비활성화" 버튼 클릭
- **예상 결과**: 상태가 "비활성"으로 변경

**TC-5.1.4: IP 차단 삭제**
- **단계**:
  1. 차단된 IP의 "삭제" 버튼 클릭
  2. 확인 대화상자에서 "확인" 클릭
- **예상 결과**: 목록에서 IP 제거

**TC-5.1.5: 자동 DDoS 감지 및 차단**
- **단계**:
  1. "의심스러운 IP 자동 차단" 체크박스 활성화
  2. 1분 내에 100회 이상 요청 시뮬레이션 (스크립트 필요)
- **예상 결과**: 해당 IP가 자동으로 차단 목록에 추가

**TC-5.1.6: Nginx 설정 파일 다운로드**
- **단계**:
  1. "Nginx 설정 다운로드" 버튼 클릭
- **예상 결과**: `ip-blacklist.conf` 파일 다운로드

#### 5.2 AdminActivityLogs 컴포넌트 테스트

**TC-5.2.1: 활동 로그 필터링**
- **단계**:
  1. 관리자 페이지 → 활동 로그 탭
  2. "전체", "로그인", "생성", "삭제", "설정" 필터 버튼 클릭
- **예상 결과**: 선택한 작업 유형의 로그만 표시

**TC-5.2.2: 날짜 범위 필터**
- **단계**:
  1. "전체", "오늘", "1주일", "1개월" 버튼 클릭
- **예상 결과**: 선택한 기간의 로그만 표시

**TC-5.2.3: 활동 로그 검색**
- **단계**:
  1. 검색창에 키워드 입력 (예: "IP 차단")
- **예상 결과**: 키워드가 포함된 로그만 필터링

**TC-5.2.4: CSV 내보내기**
- **단계**:
  1. "CSV 내보내기" 버튼 클릭
- **예상 결과**: CSV 파일 다운로드 (한글 인코딩 UTF-8 BOM)

**TC-5.2.5: 관리자 작업 자동 로깅**
- **단계**:
  1. IP 차단 추가, 설정 변경 등 관리 작업 수행
  2. 활동 로그 탭 확인
- **예상 결과**: 모든 관리 작업이 자동으로 로그에 기록

- **단계**:

- **예상 결과**: `null` 또는 빈 배열 반환

**TC-SEC-1.3: SQL Injection 방지**
- **단계**:
  1. IP 주소 입력란에 SQL 구문 입력 (예: `'; DROP TABLE admin_settings; --`)
- **예상 결과**: 정상적으로 처리되거나 검증 실패

**TC-SEC-2.1: 입력 데이터 이스케이핑**
- **단계**:
  1. 설정 입력란에 `<script>alert('XSS')</script>` 입력

- **예상 결과**: 스크립트가 실행되지 않고 텍스트로 표시

### SEC-3: CSRF (Cross-Site Request Forgery) 방지
